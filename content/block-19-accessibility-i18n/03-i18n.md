## Core Concept

**English definition:** Internationalization (i18n) in Angular encompasses both compile-time i18n (built-in `$localize`/`i18n` attribute system with XLIFF format) and runtime i18n (Transloco library), plus localization (l10n) — adapting date, number, currency formats via LOCALE_ID, locale pipes, and CLDR data.

**Пояснення:** i18n — це "підготовка" додатку до роботи на різних мовах, l10n — "пристосування" до конкретного регіону. Angular надає два шари: translation layer (яким текстом говорить UI) і localization layer (як форматуються дати, числа, валюти). Обидва потрібні для повноцінного multi-language додатку.

**Яку проблему вирішує:** Без i18n інфраструктури — hardcoded рядки в темплейтах і TypeScript, складність підтримки множини мов, відсутність перекладацьких workflows. Без l10n — "15 березня 2024" для англомовного користувача показується як "March 15, 2024", а $1,234.56 в українській локалі має бути 1 234,56 $. Ці деталі критичні для UX і довіри до продукту.

**Як працює під капотом:**

**Angular compile-time i18n:**
1. Розробник маркує рядки: `<p i18n="meaning|description@@id">Original text</p>` або `$localize\`Translate me\``
2. `ng extract-i18n` генерує XLIFF/XMB source file
3. Перекладачі заповнюють target XLIFF файли
4. `ng build --localize --configuration=uk` — компілятор Angular (через linker) замінює `$localize` template literals на відповідні переклади
5. Результат: окремий JS bundle per locale

**Transloco runtime i18n:**
1. `provideTransloco()` реєструє конфігурацію і HTTP loader
2. `TranslocoService.load(lang)` — HTTP GET `/assets/i18n/{lang}.json`
3. Переклади кешуються в Map
4. `translate(key)` — synchronous lookup, `selectTranslate(key)` — Observable
5. Зміна мови: `setActiveLang(lang)` → BehaviorSubject emit → всі `transloco` pipes re-render

**Locale pipes (DatePipe, CurrencyPipe, NumberPipe):**
- Використовують CLDR дані (зареєстровані через `registerLocaleData()`)
- Angular 16+: нативний `Intl.*` API для форматування
- `LOCALE_ID` token визначає активну locale для formatera

**Trade-offs та обмеження:**

| Підхід | Переваги | Недоліки |
|---|---|---|
| Angular compile-time | Zero runtime overhead, SEO (окремий URL per locale), tree-shaking | N builds per N locales, no runtime language switch, XLIFF complexity |
| Transloco runtime | Single build, runtime language switch, type-safe keys | HTTP request per language, bundle overhead (~15KB), async initialization |

**Версійність:**
- Angular i18n з v2, `$localize` тег з v9 (ivy)
- `ng extract-i18n` — з v9, підтримує XLIFF 1.2, XLIFF 2.0, XMB
- Transloco (заміна ngx-translate) стабільний з Angular 9+, v5+ підтримує standalone
- `registerLocaleData` обов'язковий з Angular 5+ (раніше CLDR дані включались автоматично)
- Angular 16+: Pipes використовують нативний Intl API

## Deep Details

### Edge Cases

**$localize в TypeScript:** `$localize\`Hello, ${name}!\`` — substitution підтримується, але перекладач бачить placeholder. ID генерується автоматично з hash content + meaning. Щоб ID стабільним: `$localize\`:meaning|description@@explicit-id:Hello\``.

**Transloco і SSR:** `TranslocoHttpLoader` робить HTTP запити — на сервері немає браузера. Рішення: `TranslocoLoaderSSR` що читає JSON з файлової системи, або `TransferState` для передачі translations з сервера на клієнт.

**ICU plural Ukrainian:** Українська має 4 категорії: `one` (1, 21, 31...), `few` (2-4, 22-24...), `many` (5-20, 25-30...), `other` (дроби). Без `few` та `many` — некоректна граматика.

**LOCALE_ID і runtime:** `LOCALE_ID` — статичний token, не змінюється runtime. Pipes кешують locale при першому виклику. Для runtime locale change: потрібна page reload або custom pipe implementation з dynamic locale.

**Date pipe і timezone:** За замовчуванням DatePipe використовує local timezone. `date:'yyyy-MM-dd':'UTC'` для UTC display. В SSR timezone сервера ≠ timezone клієнта.

### Junior vs Senior Understanding

**Junior знає:** як додати `i18n` атрибут, підключити Transloco, використати DatePipe.

**Senior розуміє:**

1. **$localize linker:** Під час `ng build --localize`, Angular compiler проходить по JS/TS і замінює `$localize` tagged template literals на статичні рядки. Це compile-time string substitution, а не runtime eval.

2. **CLDR data tree-shaking:** `registerLocaleData(localeUk)` реєструє дані для `uk`, але Angular не включає всі locale data автоматично (збільшує bundle). В Angular 9+ Ivy — lazy load locale data за потребою через dynamic import.

3. **Transloco reactive pipeline:** `transloco` pipe підписується на `langChanges$` Observable. При зміні мови — всі pipe instances emit нове значення через Angular CD. `reRenderOnLangChange: true` (default false) — контролює чи перерендерюються компоненти.

4. **Type-safe translations:** `@jsverse/transloco-keys-manager` генерує TypeScript type з JSON структури. `TranslocoService.translate<string>('key')` з generic. ESLint plugin для compile-time key validation.

5. **ICU in Transloco vs Angular i18n:** Transloco потребує окремий MessageFormat parser (`@jsverse/transloco-messageformat`). Angular i18n підтримує ICU нативно в compiler. Performance різниця: Angular i18n ICU — compile-time, Transloco ICU — runtime parse (кешується).

### Deprecation & Migration Path

- **ngx-translate → Transloco:** ngx-translate активно не підтримується, Transloco — рекомендована заміна. Міграція: API схожа, але не ідентична (`translate()` → `translate()`, `stream()` → `selectTranslate()`).
- **Angular i18n legacy format:** Angular 2-8 використовував `i18n-*` attribute prefix для attributes (наприклад `i18n-placeholder`). В Angular 9+ через Ivy це те саме. Але legacy `i18n="meaning|desc"` все ще підтримується.
- **`registerLocaleData` requirement:** До Angular 5 CLDR дані автоматично включались в bundle. Після — explicit registration потрібна. `ng update` не мігрує автоматично — потрібно вручну додати.
- **`DatePipe` Intl migration:** Angular 16 перейшов на `Intl.DateTimeFormat` — деякі format strings відрізняються. Наприклад, `'shortDate'` для `uk` locale може дати інший результат ніж в Angular 15.

### Connections to Other Concepts

- **ARIA & Accessibility** — переклади ARIA labels (aria-label) теж потребують i18n маркування
- **HTTP Interceptors** — Transloco HttpLoader використовує HttpClient, locale header в API запитах
- **Route Guards / APP_INITIALIZER** — preloading translations перед render
- **Performance** — lazy loading translation scopes, ServiceWorker caching

## Examples

### Basic Usage

```typescript
// Angular compile-time i18n
@Component({
  template: `
    <!-- Template маркування -->
    <h1 i18n="@@welcomeTitle">Welcome to the app</h1>

    <!-- з meaning та description -->
    <p i18n="User greeting|Displayed at login@@greetingText">Hello there!</p>

    <!-- Plural з ICU -->
    <p i18n>
      {itemCount, plural,
        =0 {No items}
        =1 {One item}
        other {{{itemCount}} items}
      }
    </p>

    <!-- Attribute translation -->
    <input [attr.placeholder]="placeholder" type="text" />
  `
})
export class AppComponent {
  itemCount = 5;
  // $localize в TypeScript
  placeholder = $localize`:input placeholder@@searchPlaceholder:Search...`;
}

// main.ts: реєстрація locale
import { registerLocaleData } from '@angular/common';
import localeUk from '@angular/common/locales/uk';
registerLocaleData(localeUk, 'uk');

bootstrapApplication(AppComponent, {
  providers: [
    { provide: LOCALE_ID, useValue: 'uk' }
  ]
});
```

```typescript
        availableLangs: ['en', 'uk', 'ar'],
        defaultLang: 'en',
        reRenderOnLangChange: true,
        prodMode: !isDevMode(),
        fallbackLang: 'en',
        missingHandler: {
          logMissingKey: !isDevMode(),
          useFallbackTranslation: true,
        },
      },
      loader: TranslocoHttpLoader,
    }),
    // ICU support
    provideTranslocoMessageformat(),
    // Preload initial language
    {
      provide: APP_INITIALIZER,
      useFactory: (transloco: TranslocoService) => () =>
        firstValueFrom(transloco.load(transloco.getDefaultLang())),
      deps: [TranslocoService],
      multi: true,
    },
  ]
};

// Feature module з scoped translations
// /assets/i18n/admin/en.json: { "users": { "title": "User Management" } }
@Component({
  selector: 'app-admin',
  imports: [TranslocoModule],
  providers: [provideTranslocoScope('admin')],
  template: `
    <ng-container *transloco="let t; scope: 'admin'">
      <h2>{{ t('admin.users.title') }}</h2>

      <!-- ICU plural з Transloco -->
      <p>{{ t('admin.users.count', { count: userCount }) }}</p>
    </ng-container>
  `
})
export class AdminComponent {
  userCount = 42;
}

// RTL підтримка
@Injectable({ providedIn: 'root' })
export class I18nService {
  private transloco = inject(TranslocoService);
  private document = inject(DOCUMENT);
  private dir$ = new BehaviorSubject<'ltr' | 'rtl'>('ltr');

  readonly RTL_LANGS = new Set(['ar', 'he', 'fa', 'ur']);

  initializeLocale(): void {
    this.transloco.langChanges$.subscribe(lang => {
      const dir = this.RTL_LANGS.has(lang) ? 'rtl' : 'ltr';
      this.document.documentElement.setAttribute('dir', dir);
      this.document.documentElement.setAttribute('lang', lang);
      this.dir$.next(dir);
    });
  }
}
```

### Anti-Example

```typescript
// ❌ Hardcoded strings — не перекладаються
@Component({
  template: `<h1>Ласкаво просимо до додатку</h1>`
})
export class BadComponent {}

// ❌ DatePipe без locale registration
// В app.config.ts:
{ provide: LOCALE_ID, useValue: 'uk' }
// Але забули registerLocaleData(localeUk)!
// Результат: runtime error "Cannot read properties of undefined"

// ❌ ICU з literal numbers замість CLDR categories
// Неправильно:
// {count, plural, =1 {1 елемент} =2 {2 елементи} other {# елементів}}
// Правильно для UK locale:
// {count, plural, one {# елемент} few {# елементи} many {# елементів} other {# елемента}}

// ❌ Synchronous Transloco translate до завантаження
@Component({
  template: `<p>{{ label }}</p>`
})
export class BadTranslocoComponent implements OnInit {
  private transloco = inject(TranslocoService);
  label = '';

  ngOnInit(): void {
    // ❌ Синхронний виклик — translations ще не завантажені
    this.label = this.transloco.translate('some.key'); // повертає 'some.key'
  }
}

// ✅ Правильно: використовувати pipe або selectTranslate Observable
@Component({
  imports: [TranslocoModule, AsyncPipe],
  template: `
    <!-- Pipe автоматично re-renders при зміні мови -->
    <p>{{ 'some.key' | transloco }}</p>

    <!-- Або Observable -->
    <p>{{ label$ | async }}</p>
  `
})
export class GoodTranslocoComponent implements OnInit {
  private transloco = inject(TranslocoService);
  label$ = this.transloco.selectTranslate('some.key');
}
```

## Code Smells and Anti-Patterns

| Anti-Pattern | Why It's Bad | Better Approach |
|---|---|---|
| Hardcoded текст в темплейтах та TypeScript | Неперекладаємо, потребує code change для кожної мови | `i18n` атрибут в темплейтах, `$localize` в TypeScript, або Transloco ключі |
| `transloco.translate('key')` до завантаження | Повертає ключ замість перекладу, silent fail | `selectTranslate('key')` (Observable) або `transloco` pipe |
| ICU plural з `=1, =2` замість CLDR categories | Не коректно для мов з 3+ plural формами (uk, ru, pl) | `one, few, many, other` CLDR categories |
| Немає `registerLocaleData()` при зміні `LOCALE_ID` | Runtime error в DatePipe/CurrencyPipe | `import localeUk from '@angular/common/locales/uk'; registerLocaleData(localeUk)` в main.ts |
| `margin-left/right` замість CSS logical properties | RTL верстка ламається — ліві відступи не інвертуються | `margin-inline-start/end`, `padding-inline-start/end`, `inset-inline-start` |

## Interview Block

### [L1 — Warm-up] Яка різниця між compile-time і runtime i18n в Angular? Коли використовувати кожен підхід?

**Signal being tested:** Чи розуміє кандидат фундаментальний trade-off між двома підходами, а не просто знає що вони існують.

**What the interviewer expects:** Чіткий trade-off: compile-time = performance/SEO, runtime = flexibility/DX. Реальні use cases для кожного.

**How to probe deeper:** "Чому compile-time i18n не підходить для SaaS де user обирає мову в профілі?" — потребує page reload при зміні мови.

**Reference answer:** Compile-time: окремий build і bundle per locale, `$localize` замінюється під час build, zero runtime overhead. Runtime (Transloco): HTTP load translations, single build, мова змінюється без reload. Вибір: SEO-critical marketing pages = compile-time (окремий URL per locale для SEO). SaaS з user preference = Transloco. Hybrid — обидва підходи в одному додатку.

**Common mistakes:** Думають ngx-translate — офіційна бібліотека. Не розуміють SEO implications (один URL для всіх мов при runtime).

---

### [L2 — Mid] Як працює ICU message format в Angular i18n? Покажи приклад plural та select.

**Signal being tested:** Знання ICU синтаксису і, головне, CLDR plural rules — типова помилка junior/mid розробника.

**What the interviewer expects:** Правильний ICU синтаксис, знання CLDR plural categories (не =1,=2), розуміння що Ukrainian має 4 plural forms.

**How to probe deeper:** "Скільки plural форм в українській мові? Назви їх." — one, few, many, other (4 форми).

**Reference answer:** ICU plural: `{count, plural, one {# елемент} few {# елементи} many {# елементів} other {# елемента}}`. CLDR категорії: `one, two, few, many, other` — залежать від locale. `=N` для exact match. ICU select для дискретних значень: `{gender, select, male {він} female {вона} other {вони}}`. Transloco потребує `provideTranslocoMessageformat()` для ICU.

**Common mistakes:** `=1, =2` замість CLDR categories. Не розуміють що `other` — обов'язковий fallback.

---

### [L3 — Senior] Як Angular locale pipes використовують LOCALE_ID і що потрібно для їх правильної роботи?

**Signal being tested:** Розуміння CLDR infrastructure, `registerLocaleData` requirement, відмінність між `LOCALE_ID` і Transloco language.

**What the interviewer expects:** `registerLocaleData` як обов'язковий крок, `LOCALE_ID` DI token, розуміння що locale (формати) і translation language — різні concerns.

**How to probe deeper:** "Що трапиться якщо встановити `LOCALE_ID: 'uk'` але не викликати `registerLocaleData`?" — runtime error в DatePipe.

**Reference answer:** `LOCALE_ID` DI token визначає locale для форматування. DatePipe, CurrencyPipe використовують CLDR дані що реєструються через `registerLocaleData(localeUk, 'uk')` — без цього runtime error. Angular 16+: Intl API для форматування. `LOCALE_ID` і Transloco lang — різні: locale='uk-UA' для форматів + transloco lang='uk' для текстів.

**Common mistakes:** Забувають `registerLocaleData`. Плутають translation language і locale.

---

### [L4 — Staff/Principal] Як реалізувати підтримку RTL мов в Angular додатку? Які аспекти необхідно врахувати?

**Signal being tested:** Системне мислення про RTL як architectural commitment — CSS strategy, tooling, testing, third-party components.

**What the interviewer expects:** CSS logical properties vs override strategy, CDK Directionality, Angular Material RTL support, testing approach, BIDI для mixed content.

**How to probe deeper:** "Як би ви організували CSS стратегію для RTL в існуючому LTR додатку?" — logical properties vs PostCSS rtlcss vs manual overrides.

**Reference answer:** RTL = architectural commitment: CSS logical properties (`margin-inline-start`) від початку — найчистіше. `dir='rtl'` на `<html>`. CDK `Directionality` service для programmatic detection. Angular Material: вбудована RTL підтримка. Icons що потребують mirror — CSS `transform: scaleX(-1)` для RTL. BIDI: `dir='auto'` для user-generated content. Testing: screenshot suite для RTL locale. Third-party charts/maps — перевірити RTL support окремо.

**Common mistakes:** Додають RTL як afterthought — `margin-left` замість logical properties ламає верстку. Не тестують BIDI для mixed content.

## Summary

### Key Points

- Angular compile-time i18n (`$localize`, `i18n` attribute) = окремий bundle per locale, zero runtime overhead, але потребує rebuild при додаванні мови.
- Transloco = single build, runtime language switch, type-safe keys — рекомендований для SaaS.
- ICU plural потребує CLDR categories (`one/few/many/other`), не literal numbers (`=1,=2`) — для мов з 3+ plural формами.
- `registerLocaleData(localeUk)` обов'язковий при зміні `LOCALE_ID` — без цього DatePipe/CurrencyPipe кидають runtime error.
- `LOCALE_ID` (форматування) і Transloco language (переклади) — різні concerns, різні DI tokens.
- RTL — architectural commitment: CSS logical properties від початку, `dir` на `<html>`, CDK `Directionality`.
- Transloco scoped translations: lazy loading per feature, `provideTranslocoScope()` в route/component providers.

### Elevator Pitch (2 minutes)

Angular i18n має два рівні: translation (яким текстом говорить UI) і localization (як форматуються дати, числа). Для translation: compile-time через `$localize` + XLIFF + `ng build --localize` — окремий bundle per locale, максимальна performance і SEO. Або Transloco для runtime — single build, HTTP-loaded translations, language switch без reload.

Для l10n: `LOCALE_ID` DI token + `registerLocaleData(localeUk)` — без цього DatePipe кидає runtime error. Pipes в Angular 16+ використовують нативний Intl API.

ICU expressions (plural/select) — стандарт MessageFormat. Критичне знання: Ukrainian має 4 plural форми за CLDR — `one/few/many/other`. `=1,=2` literal numbers — антипатерн.

RTL підтримка — це architectural рішення: CSS logical properties замість `margin-left/right`, `dir='rtl'` на html, CDK Directionality для programmatic detection.
