## Core Concept

**English definition:** End-to-End (E2E) testing verifies user workflows through the complete application stack — browser, Angular app, HTTP calls, and backend — simulating real user interactions to confirm the application works as a whole.

**Пояснення:** E2E тести запускаються в реальному браузері, завантажують реальний Angular додаток, і симулюють дії користувача (кліки, введення тексту, навігацію). На відміну від unit тестів — немає мок сервісів, немає ізоляції — реальна взаємодія між всіма шарами.

**Яку проблему вирішує:**
- **Integration gaps:** Юніт тести перевіряють частини, E2E — що вони правильно з'єднані
- **User journey validation:** Перевірити що multi-step workflow (signup → dashboard → action) реально працює
- **Regression prevention:** Змінення в одному місці не зламало інший user flow
- **Cross-browser:** Playwright тестує в Chromium, Firefox, WebKit одним набором тестів

**Як працює під капотом:**

```
E2E Test
  ↓
Playwright/Cypress (browser automation)
  ↓
Real browser (Chromium/Firefox/WebKit)
  ↓
Angular app (ng build + serve)
  ↓
HTTP requests to API (real or mocked)
  ↓
Assertions on DOM/network/state
```

```typescript
// Playwright example
import { test, expect } from '@playwright/test';

test('user can login and see dashboard', async ({ page }) => {
  await page.goto('/login');
  await page.fill('[data-testid="email"]', 'user@test.com');
  await page.fill('[data-testid="password"]', 'password123');
  await page.click('[data-testid="login-btn"]');

  await expect(page).toHaveURL('/dashboard');
  await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible();
});
```

**Trade-offs та обмеження:**
- **Slow:** Секунди на тест замість мілісекунд — suite з 100 тестів = хвилини
- **Flaky:** Timing issues, network instability, test isolation challenges
- **Expensive:** CI compute time, parallelization costs
- **Maintenance:** DOM changes require test updates even when behavior unchanged
- **Protractor deprecated:** Angular 12 — офіційний E2E tool deprecated, CLI пропонує Playwright

**Версійність:**
- Angular 2-11: Protractor — офіційний Angular E2E tool
- Angular 12: Protractor deprecated, Angular CLI надає вибір між Playwright/Cypress при ng new
- Angular 17+: `ng new` з `--e2e=playwright` або `--e2e=cypress` (або `--e2e=none`)
- Playwright: actively developed, Microsoft-backed, Angular team рекомендація для нових проєктів
- Cypress: встановлена Angular community, компонентний testing тепер підтримує Angular

## Deep Details

### Edge Cases

**Angular stability — чекати коли Angular готовий:**
```typescript
// Playwright — дочекатись Angular stability перед assertions
// Angular DevTools Protocol integration
import { test, expect } from '@playwright/test';

test('wait for Angular', async ({ page }) => {
  await page.goto('/products');

  // Playwright автоматично чекає network idle, але Angular може ще рендерити
  // Explicit wait для Angular-specific loading
  await page.waitForSelector('[data-testid="product-list"]', { state: 'visible' });

  // Або через waitForFunction
  await page.waitForFunction(() => {
    return document.readyState === 'complete' &&
      !document.querySelector('.loading-spinner');
  });
});
```

**data-testid convention:**
```html
<!-- Angular template — стабільні selectors для E2E -->
<!-- НЕ класи (змінюються при redesign) -->
<button class="btn btn-primary" (click)="submit()">Submit</button>
<!-- НЕ ids (можуть дублюватись) -->
<input id="email" [(ngModel)]="email">

<!-- ✅ data-testid — explicit testing contract -->
<button data-testid="login-submit-btn" (click)="submit()">Submit</button>
<input data-testid="login-email-input" [(ngModel)]="email">
```

**Network mocking в E2E:**
```typescript
// Playwright — mock API responses для deterministic tests
test('should show product catalog', async ({ page }) => {
  await page.route('/api/products', async route => {
    await route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify([
        { id: '1', name: 'Widget', price: 9.99 },
        { id: '2', name: 'Gadget', price: 19.99 },
      ]),
    });
  });

  await page.goto('/products');
  await expect(page.getByTestId('product-list')).toContainText('Widget');
  await expect(page.getByTestId('product-list')).toContainText('Gadget');
});
```

### Junior vs Senior Understanding

**Junior** знає: "Playwright/Cypress пишемо test, click, fill, expect. data-testid для selectors."

**Senior** розуміє testing pyramid і E2E trade-offs: E2E для critical journeys, не для всієї логіки. Page Object Model для maintenance. Network mocking для determinism в CI. Parallel sharding для performance. Flakiness management стратегію. Accessibility testing integration.

```typescript
// Senior: Page Object Model implementation
// e2e/pages/login.page.ts
import { Page, expect } from '@playwright/test';

export class LoginPage {
  constructor(private page: Page) {}

  async goto(): Promise<void> {
    await this.page.goto('/login');
    await this.page.waitForSelector('[data-testid="login-form"]');
  }

  async fillEmail(email: string): Promise<void> {
    await this.page.fill('[data-testid="login-email"]', email);
  }

  async fillPassword(password: string): Promise<void> {
    await this.page.fill('[data-testid="login-password"]', password);
  }

  async submit(): Promise<void> {
    await this.page.click('[data-testid="login-submit"]');
  }

  async expectValidationError(message: string): Promise<void> {
    await expect(
      this.page.getByTestId('login-validation-error')
    ).toContainText(message);
  }

  async login(email: string, password: string): Promise<void> {
    await this.goto();
    await this.fillEmail(email);
    await this.fillPassword(password);
    await this.submit();
  }
}

// e2e/tests/auth.spec.ts
import { test, expect } from '@playwright/test';
import { LoginPage } from '../pages/login.page';

test.describe('Authentication', () => {
  test('successful login navigates to dashboard', async ({ page }) => {
    const loginPage = new LoginPage(page);
    await loginPage.login('user@test.com', 'password');

    await expect(page).toHaveURL('/dashboard');
  });

  test('invalid credentials show error', async ({ page }) => {
    const loginPage = new LoginPage(page);
    await loginPage.goto();
    await loginPage.fillEmail('wrong@test.com');
    await loginPage.fillPassword('wrong');
    await loginPage.submit();

    await loginPage.expectValidationError('Invalid credentials');
    await expect(page).toHaveURL('/login'); // stays on login
  });
});
```

### Deprecation & Migration Path

- **Deprecated (Angular 12):** Protractor — офіційно deprecated, виходить з maintenance
- **Migration path:** Protractor → Playwright через `@playwright/test` (community migration guides)
- Angular CLI 12+ не генерує Protractor config за замовчуванням
- Angular 17+: `ng generate @angular/builders:playwright --project=app` для scaffolding
- ng-e2e schematic від Cypress: `ng add @cypress/schematic`

### Connections to Other Concepts

- **Testing Pyramid:** E2E — вершина піраміди; unit — база
- **Service Workers:** Playwright може тестувати offline behavior і SW update scenarios
- **SSR/Hydration:** E2E єдиний спосіб тестувати hydration correctness в realistic context
- **Accessibility:** axe-core integration через Playwright/Cypress для automated a11y

### Production Scenario

```typescript
// e2e/tests/checkout.spec.ts — critical user journey test
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

test.describe('Checkout Flow', () => {
  test.use({ storageState: 'e2e/.auth/user.json' }); // pre-authenticated state

  test('complete checkout flow with accessibility check', async ({ page }) => {
    // Accessibility check on checkout page
    await page.goto('/cart');
    const a11yResults = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa'])
      .analyze();
    expect(a11yResults.violations).toHaveLength(0);

    // Add item and proceed
    await page.getByTestId('add-to-cart-btn').first().click();
    await page.getByTestId('checkout-btn').click();
    await expect(page).toHaveURL('/checkout');

    // Fill shipping details
    await page.fill('[data-testid="shipping-name"]', 'Alice Smith');
    await page.fill('[data-testid="shipping-address"]', '123 Main St');
    await page.fill('[data-testid="shipping-city"]', 'Kyiv');
    await page.selectOption('[data-testid="shipping-country"]', 'UA');

    // Payment (mocked)
    await page.fill('[data-testid="card-number"]', '4242424242424242');
    await page.fill('[data-testid="card-expiry"]', '12/25');
    await page.fill('[data-testid="card-cvv"]', '123');

    await page.click('[data-testid="place-order-btn"]');

    // Order confirmation
    await expect(page).toHaveURL(/\/orders\/[\w-]+\/confirmation/);
    await expect(page.getByTestId('order-success-msg')).toBeVisible();
    await expect(page.getByTestId('order-id')).toBeVisible();
  });
});

// e2e/global-setup.ts — pre-authenticate for performance
import { chromium, FullConfig } from '@playwright/test';

async function globalSetup(config: FullConfig): Promise<void> {
  const browser = await chromium.launch();
  const page = await browser.newPage();

  await page.goto('http://localhost:4200/login');
  await page.fill('[data-testid="email"]', 'e2e-user@test.com');
  await page.fill('[data-testid="password"]', 'E2EPassword123!');
  await page.click('[data-testid="login-submit"]');
  await page.waitForURL('**/dashboard');

  // Save auth state — reuse across tests (much faster than re-logging each test)
  await page.context().storageState({ path: 'e2e/.auth/user.json' });
  await browser.close();
}

export default globalSetup;
```

```typescript
  await page.fill('[data-testid="price"]', '100');
  await page.fill('[data-testid="rate"]', '20');
  await expect(page.getByTestId('tax-result')).toContainText('20.00'); // unit test territory
});

// ❌ WRONG: No retry, no proper waiting
test('bad async handling', async ({ page }) => {
  await page.click('#submit');
  // Immediately check without waiting for async response
  expect(await page.textContent('.result')).toBe('Success'); // race condition
});

// ✅ CORRECT: data-testid + proper async waiting
test('good async handling', async ({ page }) => {
  await page.click('[data-testid="submit-btn"]');
  // Wait for the response to render
  await expect(page.getByTestId('success-message')).toBeVisible({ timeout: 10_000 });
});
```

## Code Smells and Anti-Patterns

| Anti-Pattern | Why It's Bad | Better Approach |
|---|---|---|
| CSS class selectors в E2E | Break on visual redesign — tests fail without functional regression | `data-testid` attributes або ARIA roles/labels |
| E2E для business logic testing | Slow, fragile — unit test covers same ground 100x faster | Unit tests для logic, E2E для user journeys |
| No Page Object Model в large test suite | Hundreds of selectors duplicated — one DOM change breaks everything | POM з encapsulated selectors і actions |
| E2E проти live production API | Non-deterministic, може affect real data, flaky | Mock server (MSW) або staging environment |
| No retry/quarantine для flaky tests | Один flaky test блокує весь CI pipeline | `retries: 2` в config, quarantine consistently flaky tests |

## Interview Block

### [L1 — Warm-up] Що таке E2E тестування і чим воно відрізняється від unit тестів?
**Signal being tested:** Розуміння testing pyramid і ролі кожного рівня
**What the interviewer expects:** Реальний браузер vs jsdom, full stack vs isolated, повільніше vs швидше, Protractor deprecated
**How to probe deeper:** "Коли б ти НЕ писав E2E тест для нової функції?"
**Reference answer:** E2E = реальний браузер + реальний Angular bootstrap + реальні HTTP calls (або мок). Unit = ізольований component/service в jsdom. E2E: хвилини, flaky, дорогі. Unit: мілісекунди, fast, reliable. E2E для: критичні user journeys, cross-browser. Unit для: бізнес логіка, component behavior. Protractor deprecated Angular 12 — Playwright або Cypress.
**Common mistakes:** E2E для кожної логіки; не знають про Protractor deprecation

### [L2 — Mid] Playwright vs Cypress для Angular — ключові відмінності?
**Signal being tested:** Awareness про E2E tool ecosystem і Angular-specific considerations
**What the interviewer expects:** Multi-browser support (Playwright), DX Cypress, Angular CLI default, parallel execution trade-offs
**How to probe deeper:** "Як би ти вибрав між ними для нового Angular проєкту?"
**Reference answer:** Playwright: Chromium/Firefox/WebKit з одного API, параллельний по default, TypeScript first, Angular team рекомендація. Cypress: кращий DX (time-travel debugging), встановлена Angular community, Cypress Component Testing. Playwright краще для CI multi-browser; Cypress для development debugging. Angular 17+ CLI: Playwright default.
**Common mistakes:** Думають Cypress тільки Chrome; не знають що Angular CLI тепер рекомендує Playwright

### [L3 — Senior] Як реалізувати Page Object Model для Angular E2E тестів?
**Signal being tested:** Practical POM implementation knowledge і selector strategy
**What the interviewer expects:** POM class per page, data-testid selectors, action methods, navigation helpers, component objects
**How to probe deeper:** "Як б ти організував POM для компонента що reuses на 5 різних сторінках?"
**Reference answer:** Page Object клас з encapsulated data-testid selectors і action methods (goto(), fillForm(), submit()). Component Object для reusable components (HeaderPO, TablePO). data-testid — stable selectors (не CSS, не ids). Login flow: pre-authenticate once in globalSetup, reuse storageState для performance.
**Common mistakes:** CSS class selectors в POM; одна гігантська page object замість composition

### [L4 — Staff/Principal] Як організувати E2E тести в CI/CD pipeline?
**Signal being tested:** Infrastructure thinking — reliability, performance, cost, feedback speed
**What the interviewer expects:** Sharding, mock backend strategy (MSW vs staging), retries, smoke vs regression triggers, flakiness management, accessibility in pipeline
**How to probe deeper:** "Як вирішити trade-off між testing against real API і mock API в CI?"
**Reference answer:** Sharding (Playwright --shard N/M) для паралелізації. Mock backend (MSW/json-server) для determinism і speed vs real backend для реалізму. Smoke tests на кожному PR (critical paths only), full regression nightly. retries: 2 для flakiness mitigation. Accessibility: @axe-core/playwright в CI. Flakiness metrics: track і quarantine consistently flaky tests. Cost analysis: E2E CI time vs bugs caught.
**Common mistakes:** E2E проти production API; немає retry; full suite на кожному PR (занадто повільно)

## Summary

### Key Points
- E2E тести = реальний браузер + повний Angular stack — для critical user journeys, не бізнес логіки
- Protractor deprecated (Angular 12) — Playwright (Angular CLI default) або Cypress
- `data-testid` attributes — стабільні selectors що не ламаються при redesign
- Page Object Model — encapsulate selectors і actions, DRY selector maintenance
- Playwright: multi-browser (Chromium/Firefox/WebKit), native parallel, TypeScript first
- Cypress: кращий DX (time-travel debug), Angular community history, Component Testing
- `@axe-core/playwright` або `cypress-axe` — automated accessibility testing в E2E suite
- CI optimization: sharding, smoke vs regression triggers, retries для flakiness, mock backend

### Elevator Pitch (2 minutes)
"E2E тести запускаються в реальному браузері і тестують весь Angular стек разом — від UI до API. Protractor deprecated в Angular 12, зараз використовують Playwright (рекомендований Angular CLI) або Cypress. Playwright: multi-browser (Chromium/Firefox/WebKit), паралельний, TypeScript first, кращий для CI. Cypress: кращий DX, time-travel debug, встановлена Angular community. Ключові практики: data-testid атрибути замість CSS class selectors (стабільні при redesign), Page Object Model для encapsulation selectors і actions, network mocking (page.route()) для deterministic CI tests. Accessibility: @axe-core/playwright для automated WCAG checks в E2E suite — ~30-40% WCAG покриття автоматично. CI: sharding (Playwright --shard N/M) для паралелізації, retries для flakiness, smoke tests на PR, full regression nightly. E2E правило: тестувати критичні user journeys, не бізнес логіку — для логіки unit тести набагато ефективніші."
